# Google Chatと連絡管理人

このMacのPersonal版から、ローカルのGoogleChatExtensionMCPへ接続する。開発をボットに依頼する機能ではない。Google Chatの通常Web画面を専用ヘッドレスChromiumで読み、Google API・Cookieの書き出し・外部公開は使わない。

## 使い方

「連絡管理人」の登録済み会話へ通知する。本文をMac上で登録語句置換した後、このボットの既存エンジンによるツールなし判定へ渡す。本人に新たな返答・判断・予定確認が必要な場合だけ、短い日本語で知らせる。重要そうというだけの案内、雑談、定例の案内、他人宛ての依頼、解決済みの内容は通知しない。取得原文・引用の全文転送や、判定失敗時の原文fallbackはない。

他人への一般的な交代募集は、本人への新たな対応がなければ通知しない。本人への交代の申し出や確定は区別し、返答や本人の予定確認が必要な場合に知らせる。通知判定には行動用ツールを渡さず、カレンダーの空きを断定しない。予定確認や変更、Google Chatへの返信は、本人が会話で依頼した場合の通常のツール経路で行う。

送信者の表示名が「自分」でもdirectionがincomingでも本人として判定する。引用の名前を送信者にしない。判定文脈は直近30件・24,000文字以内へ絞ってから登録語句を置換し、構造化結果とJSON文字列を重複して渡さない。実編集には置換済みの変更前本文と前回通知も添え、新たな対応が増えたかを比較させる。取得・置換・判定・通知保存に失敗した投稿はcursorを進めない。

対象はGoogleChatExtensionMCPの`config.json`に登録したスレッドのみ。`get_monitored_thread`と`reply_to_monitored_thread`は対象が1件のときだけ動き、モデルがSpace名やIDを作る必要はない。送信直前に実画面のSpace・URL・返信regionのtopic・入力文を照合し、送信後は自分の新規投稿DOMを確認する。結果不明の送信は新しいキーで自動再試行しない。仮名が残る送信文も拒否する。

## 保護と配送

接続先は同じMacの`http://127.0.0.1:17321`。Bearerは`private/google-chat.json`に0600で保存し、設定APIの応答やモデル入力には返さない。接続設定は所有者のloopback APIだけで変更できる。MCPは登録したボットの個人会話にだけ組み込み、他のボット・グループへ自動で公開しない。自動起動・委任・継続処理には読み取り専用の接続を渡す。

受信テキストは登録語句だけをこのMacで置換してから会話へ保存する。OpenAI privacy-filterと日本語補助ルールによる自動検出は削除した。未登録の氏名・メール・住所などはそのまま通る。接続ボットのMCP等の取得結果も既存のローカル置換プロキシを通す。処理失敗時に原文へ戻す経路はない。表示専用の復元と復元下書きは維持し、自動送信しない。

1結果100,000文字・16,384文字列までの構造化結果を扱う。画像・音声・リソース等は対象の保護経路で拒否する。通常チャットの自動適用がオフでも、この接続の登録語句置換は動く。CLIの独自ファイル読取等は対象外である。

Bridgeは新着差分をSQLiteへ記録する。アプリは認証付きロングポーリング（待機最大25秒、差分検出後は最大約200msで応答）で受け取り、登録語句置換後に通知判定へ渡す。`private/google-chat-receipts.json`には宛先・投稿・本文のハッシュと短い判定済み通知を0600で保存し、通知不要の判定も保持する。同じ本文が新しい差分番号で届いても再判定・再通知しない。通知保存と処理履歴保存が終わってからcursorを進め、通知保存直後の停止も会話内の意味単位のreceiptで重複を防ぐ。

初回の過去履歴は通知せず、以後は永続cursorと会話内の配送receiptで重複を防ぐ。フィルター異常時はcursorを進めない。アプリ停止中の差分はBridgeに残り、再開後に処理する。Bridge再接続時も、保存済みwatermarkより新しい未取得投稿はローカル差分へ記録する。未描画・削除済み・同一時刻等の投稿まで完全に遡って保証するものではない。

DOM抽出は引用ブロック、ボタン、引用内見出し、名前読込表示を本文から除き、送信者名や時刻の変化を本文編集として扱わない。読み込み中の送信者は確定まで保留する。`contentVersion:3`への初回移行では既存本文の基準だけ更新し、履歴行を削除しない。同じ版での再接続は以前の本文を維持し、3秒の回復待機と1.5秒以上離れた一致観測の後、実際の本文編集を差分へ記録する。通常の本文編集も一致観測を待つため、通知確定は次の収集時（通常最大約15秒）になる。新規投稿はこの編集待機の対象外である。

アプリが終了している間は通知できない。監視専用ブラウザの停止はBridgeが復旧を試み、認証切れ・取得異常は会話へ知らせる。Macの電源断・スリープ・閉じた蓋をヘッドレスで回避することはできない。大学SSOの再認証とGoogleの画面変更への対応まで永久に不要とは保証しない。

## 設定と検証

通知先の保存は接続成功ではない。設定APIは保存時にも監視状態を即時確認し、`registered`と`monitorReady`を別々に返す。保存だけで「接続しました」や新着受信の約束を会話に追加しない。本文診断の前後で監視状態を再確認し、ログイン切れ・収集停止時は保存済み本文があっても`MONITOR_NOT_READY`で拒否する。前回セッションの成功記録は`previousBody`に残し、現在の成功表示には使わない。再ログインが未解消の間の収集途絶・通信失敗は、同じログイン問題の通知としてまとめる。

コンパイル済みUIへ表示文だけを反映した場合は、署名前に`cache-bust-staged-ui.mjs /absolute/staged.app/Contents/Resources/ui`を実行する。JSファイル名と相互参照・HTMLの入口を同じ識別子へ更新し、遅延ロードした設定画面に古いコードキャッシュが残らないようにする。通常のソースからのViteビルドは自動で内容ハッシュを更新する。

既存の配布用アプリへ通知修正だけを反映する場合、`runtime/active.json`が示すRuntime.appを`.privacy-dev/personal-build/`内へ複製する。`scripts/build-google-chat-notification-patch.mjs`にserver/index.jsを渡すと、通知モジュールと既存エンジン・保存先への依存だけを差し替える。`patch-google-chat-notification-ui.mjs`へui/assetsを渡し、続けて上記cache-bustを行う。署名・検証後、専用manifestを`personal-install-runtime.mjs --package /absolute/package.json`へ渡して切り替える。通常更新では固定ランチャーを変更しない。

別バンドルの`PASS`は本体ルーターの同名Symbolと同一ではない。本体の`scopeGoogleChatRoute`か反映スクリプトの同等の境界で、Google Chat対象外のURL・メソッドは本体の`PASS`を返す。これがないと認証状態確認などの後続ルートが応答せず、画面起動を止める。配布版検証では`/api/auth/session`と存在しないURLの応答も確認し、`--ui`指定時は架空のデスクトップ所有者能力を使い、設定画面の表示まで確認する。実アプリのトークンを使う検証ではない。

`node scripts/google-chat-connection-acceptance.mjs /absolute/staged.app/Contents/Resources/server/index.js`は隔離HOMEと架空Bridge・モデルで、LOGIN_REQUIRED時の登録と稼働の分離、本文診断前後のログイン切れ、AI判定を通る短い通知、雑談抑制、実編集、新しい差分番号での再起動後の重複抑制、判定失敗時の保留、判定への行動用ツール不提供を検証する。Google Chatへの書き込みは0回。実アカウントの新着を使った検証とは別である。

Personalアプリの「設定」→「一般」→「Google Chat連携」で「連絡管理人」を選び、「通知先を登録・状態確認」を押す。Bridge認証情報はMac内で読み込む。同じ画面で状態確認と受信停止ができる。ローカルの置換用モデルは不要だが、通知判定には登録したボットの既存エンジン接続が必要。置換ルールは「登録語句の置換」で設定する。

「監視接続」と「本文取得・マスク」は別の状態として表示する。「本文取得を診断」は登録済みスレッドを読み、実際のローカルフィルターを完了させ、件数だけを返す。本文を画面・会話・通知判定AIに出さず、Google Chatに投稿しない。これは新着通知の選別・配送確認とは別である。

MCPのテキストJSONと構造化`result`が完全一致するときは構造化データを一度だけ保護し、その処理済みデータからテキストJSONを再生成する。一致しない追加テキストは省略せず通常のフィルターを通す。既存の件数・構造・画像等の拒否条件、登録語句、仮名化は維持する。

診断は`private/google-chat-diagnostics.json`（0600、最大64処理・各12段階）に開始／終了時刻、所要時間、停止段階と固定の失敗コードだけを残す。本文、氏名、トークン、URL、任意の例外文やスタックは保存しない。差分取得は45秒、本文取得の通信は15秒、本文マスク全体は120秒で打ち切り、失敗時は未処理cursorを保持する。MCPプロキシでは上流待ちを30秒、マスク応答待ちを135秒で制限する。Codex側にも既存の`mcpCallTimeoutMs`を秒へ変換して起動・再開の両方へ渡す（未指定時はOpenMausBotの既定10分）。これによりマスクの完了前にCodexの標準60秒で切れる不一致を避ける。

管理ブラウザ方式の更新途絶は`COLLECTOR_STALE`、ブラウザ停止は`BROWSER_OFFLINE`。使っていない拡張への`EXTENSION_OFFLINE`を返さない。接続・認証・差分解析・マスク・保存は別コードで通知する。同一障害は初回だけ通知し、再起動をまたいで抑制する。正常が30秒以上継続した後に復旧を1回通知する。監視接続の復旧通知は本文取得の成功を意味しない。

`GET /api/google-chat`は秘密を含まない接続状態、宛先、cursorを返す。`PUT`は`enabled`、`url`（loopbackの`/mcp`のみ）、`token`、既存の`botId`・`threadId`を受け取る。通常のAPI設定やワークスペースバックアップには秘密を含めない。既存の会話・ボット設定を置き換えない。

`node_modules/.bin/vitest run server/google-chat.test.ts server/google-chat-notification.test.ts server/google-chat-diagnostics.test.ts server/routines.test.ts server/privacy` は架空データでローカルマスク、一般通知の要約と研究・ゼミのお知らせ、不要通知の抑制、本人募集への申し出と交代確定の区別、場所不明時に可否を断定しないこと、処理キューの冪等性、失敗時のcursor保持、読み取り専用予定確認と権限の範囲を検証する。実Google Chat Bridgeや実カレンダーの検証ではない。大学Chatにはテスト投稿しない。
